# ADMA Automatic Backup V1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an automatic, service-only logical database and incremental Storage backup subsystem to the ADMA production Supabase project, with validated manifests, ten-snapshot retention, and a non-writing restore dry-run.

**Architecture:** A repeatable-read PostgreSQL RPC serializes every registered application table into deterministic, lossless NDJSON staging chunks. The `backup-adma` Edge Function copies those chunks and content-addressed Storage blobs into the private `adma-backups` bucket, validates them, writes the completion manifest last, and applies reference-aware retention. Pure modules isolate checksums, manifests, Storage deduplication, retention, and restore planning for Node unit tests.

**Tech Stack:** PostgreSQL 17, Supabase migrations/RLS/Vault/pg_cron/pg_net/Storage/Edge Functions, Deno TypeScript, Node.js 22 built-in test runner, Web Crypto SHA-256.

**Spec:** `docs/superpowers/specs/2026-09-11-backup-v1-design.md`

- Backup V1 remains in the same Supabase project and is not disaster recovery for total project/account loss.

- [ ] **Step 3: Implement `backup_runs`, private staging, and the registry**

Create the exact schema from the approved design. Seed the registry with the 24 included application tables and the two excluded public service tables after adding `backup_runs`. Give private tables no `anon`/`authenticated` privileges. Store no production row values in the migration.

The table registry interface is:

```sql
create table private.backup_table_registry (
  table_name text primary key,
  included boolean not null,
  excluded_columns text[] not null default '{}',
  exclusion_reason text,
  check (included or exclusion_reason is not null)
);
```

The staging chunk key is `(run_id, table_name, chunk_index)`, and each chunk records `row_count`, `body`, `bytes`, and a 64-character SHA-256 checksum.

- [ ] **Step 4: Implement atomic claim and terminal-state RPCs**

`claim_backup_run(p_backup_id text, p_force boolean default false)` returns one of `started`, `skipped_recent`, or `already_running` with a run identifier. Inside one transaction it marks running rows older than 15 minutes failed, applies the 72-hour successful-backup rule, and relies on the partial unique index to prevent concurrent claims.

`finish_backup_run(...)` accepts only a currently running run, writes counts/checksum/duration, and changes it to success. `fail_backup_run(...)` sanitizes error text to 1,000 characters and never modifies a terminal success.

- [ ] **Step 5: Implement repeatable-read serialization RPCs**

`prepare_backup_snapshot(p_run_id uuid)` validates registry/schema parity, refuses unclassified tables or secret-like unclassified columns, discovers PK/FK/type metadata, and uses generated `json_build_object` expressions in ordinal column order. Numeric columns use `column::text`; rows use the complete PK order. Split into 500-row NDJSON chunks and create one empty chunk for empty tables.

Restrict dynamic identifiers to values read from `pg_catalog`, quote them with `%I`, qualify all schemas, use an empty search path, and expose no table-name parameter to the caller.

`read_backup_table_page(p_table_name text, p_after jsonb, p_limit integer)` accepts only an included registry table and returns the same canonical serialization for restore comparison. Limit pages to 500 rows.

- [ ] **Step 6: Add private bucket, Vault auth, and Cron**

Insert `adma-backups` with `public=false`; create no Storage policy. Create `backup_cron_secret` only if absent, expose only the boolean verifier to `service_role`, and schedule `backup-adma-daily-check` at `43 2 * * *` with a Vault-backed `X-Backup-Secret` header and 30-second request timeout.
